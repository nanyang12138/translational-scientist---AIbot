# 阶段性干净状态与上下文继承机制研究记录

## 1. 背景问题

我们讨论的问题不是单纯的“上下文窗口不够长”，而是长上下文和多轮 Agent 任务中出现的上下文污染：

- 旧目标、旧假设和旧回答会继续影响新阶段判断。
- 语义相关但当前目标不兼容的信息，比完全无关信息更容易误导模型。
- 模型容易把过程中的临时推理、错误尝试或已废弃方案当成后续阶段的事实。
- 百万上下文可以作为档案库，但不适合作为每一轮推理的默认工作台。

更接近根本的问题是：

> AI 不应该用“越来越长的上下文”持续思考，而应该在每个阶段结束后，把阶段轨迹清洗为可继承的干净状态，再以新的上下文进程继续。

## 2. 人类式阶段思考的启发

人类在做复杂任务时，通常不是把全部过程细节都放在工作记忆里，而是分阶段推进：

1. 先分析问题。
2. 得到阶段性结论。
3. 抛弃过程噪声。
4. 保留关键结论、约束、证据和下一步目标。
5. 进入下一阶段。

这说明真正需要的不是无限工作记忆，而是持续更新的状态账本：

```text
目标
当前阶段
已确认结论
已废弃假设
关键证据
未解决问题
下一步
```

## 3. 与 SelfCompact 的关系

检索到的相近方向包括 Self-Compacting Language Model Agents。其核心思想是：

```text
不是在 token 快满时压缩，
而是在子任务完成或轨迹收敛时压缩。
```

SelfCompact 已经证明：

- 固定 token 阈值压缩容易在推理中间误删关键中间状态。
- 让模型配合轻量 rubric 判断压缩时机，可以降低 token 成本。
- 在数学和 agentic search 任务中，决策式压缩优于不压缩或固定间隔压缩。

但 SelfCompact 更偏向解决：

> 什么时候压缩？

我们希望进一步研究的是：

> 压缩后，什么有资格成为下一阶段的真实状态？

因此二者关系可以概括为：

```text
SelfCompact = timing problem
我们的方向 = state admission + evidence preservation + clean restart problem
```

## 4. 三个关键局限与研究切入点

### 4.1 局限一：清洗器本身可能总结错

如果输出处理器把关键细节删掉，下一阶段会在失真的状态上继续。

常见问题包括：

- 漏掉关键约束。
- 把假设写成事实。
- 把失败路径删掉。
- 把不确定结论压缩成确定结论。
- 丢失证据来源。
- 把用户明确否定过的方向重新包装成可行方案。

因此，不能只做自然语言摘要，而应做结构化状态蒸馏：

```text
确认事实
决策
当前假设
废弃假设
约束
证据链接
未解决问题
下一步
```

核心区别：

```text
普通摘要：把历史变短。
状态蒸馏：把历史转化为可验证、可继承的任务状态。
```

### 4.2 局限二：有些内容不能摘要，只能回溯原文

法律文本、专利权利要求、代码 diff、实验数据、数学证明等高精度内容不能只靠摘要继承。

正确结构应是：

```text
完整历史 / 原始证据 → 外部证据档案
阶段结论 / 当前状态 → 干净状态账本
下一轮推理 → 默认读取干净状态，必要时按证据索引回查原文
```

也就是说：

> 百万上下文不是工作台，而是档案库。

每条关键状态都应绑定原始证据指针，例如：

```json
{
  "claim": "SelfCompact 已覆盖阶段触发压缩的一部分思想",
  "source_refs": ["search_result:selfcompact:lines_12_34"],
  "confidence": 0.9,
  "allowed_use": "prior_art_boundary"
}
```

### 4.3 局限三：阶段边界不好判断

什么时候算“阶段完成”并不简单。

如果过早压缩，会丢失中间变量；如果太晚压缩，旧噪声继续污染后续推理。

SelfCompact 使用轻量 rubric，例如：

```text
子任务是否完成？
轨迹是否收敛？
是否处于推理中间？
是否卡住？
```

但这仍可能误判。因此需要多信号阶段边界判定器，而不是只让模型自判。

可用信号包括：

- 当前阶段是否产生明确产物。
- 产物是否通过验证。
- 是否还有未解决依赖。
- 是否存在未解决冲突。
- 用户是否接受或推动进入下一阶段。
- 工具结果是否稳定。
- 当前输出是否可以独立复用。
- 是否仍有新错误或反例尚未处理。

## 5. 建议的新方案：阶段性可验证状态继承机制

暂定名称：

> 阶段性可验证状态继承机制  
> Verifiable Stage-State Inheritance

核心思想：

```text
每一阶段允许模型充分发散和探索；
但阶段结束时，完整发散轨迹不能直接进入下一阶段；
必须经过状态蒸馏、证据绑定、准入验证；
然后用干净状态开启新的上下文进程。
```

系统流程：

```text
当前阶段输入
  ↓
LLM 推理 / 搜索 / 执行
  ↓
阶段边界判定器
  ↓
结构化状态蒸馏器
  ↓
证据绑定器
  ↓
状态准入验证器
  ↓
干净上下文编译器
  ↓
新进程开始下一阶段
```

## 6. 核心机制

### 6.1 阶段状态账本

阶段状态账本保存可继承状态，而不是保存完整聊天记录：

```json
{
  "stage_id": "S3",
  "stage_goal": "确定区别于 SelfCompact 的创新点",
  "accepted_state": [
    {
      "claim": "SelfCompact 已覆盖阶段触发压缩的部分思想",
      "evidence": ["search_result_selfcompact_001"],
      "confidence": 0.9
    }
  ],
  "rejected_state": [
    {
      "claim": "仅做普通摘要可作为创新点",
      "reason": "已有 recursive summarization 和 context compaction",
      "evidence": ["prior_art_summary_003"]
    }
  ],
  "open_questions": [
    "如何验证状态蒸馏没有丢失关键约束？",
    "如何判断阶段边界？"
  ],
  "next_stage_input": "围绕状态准入和证据绑定构造专利方案"
}
```

### 6.2 状态准入

不是所有输出都有资格成为下一阶段输入。

流程应为：

```text
模型输出
  ↓
拆解为候选状态增量
  ↓
验证
  ↓
绑定证据
  ↓
通过者写入 accepted_state
  ↓
未通过者写入 rejected_state / quarantined_state
```

这个机制比“摘要”更关键：

> 不是把所有内容变短，而是判断哪些内容有资格成为下一阶段的现实。

### 6.3 证据绑定

每条状态项应至少包含：

```text
source_ref
confidence
scope
allowed_use
superseded_by
```

这样可以防止摘要漂移，也便于回溯。

### 6.4 干净进程重启

下一阶段不继续追加完整聊天记录，而是重新编译输入：

```text
系统规则
当前阶段目标
上一阶段 accepted_state
上一阶段 rejected_state
必要证据索引
下一步任务
```

完整历史默认不进入上下文，只作为可查询档案。

## 7. 与相邻技术的区别

| 相邻方向 | 已有技术重点 | 本方向切入点 |
|---|---|---|
| 普通摘要 | 把历史变短 | 容易失真，缺少状态准入 |
| SelfCompact | 判断何时压缩 | 未充分解决压缩后状态是否可信 |
| MemGPT / Letta | 内外记忆分页 | 更偏记忆管理，不一定有阶段准入 |
| Memex | 摘要 + 原文索引 | 接近，但重点是经验索引，不是阶段状态继承 |
| Git Context Controller | commit / branch / merge 管理上下文 | 接近，但更像版本控制框架 |
| Governance Decay 防御 | 防止压缩丢安全约束 | 本方向扩展到目标、证据、废弃假设和阶段产物 |

## 8. 可能的实验设计

### 8.1 实验 A：摘要失真测试

比较对象：

1. 普通摘要。
2. SelfCompact。
3. 结构化状态蒸馏。
4. 结构化状态蒸馏 + 证据绑定。

指标：

```text
关键事实保留率
约束保留率
废弃假设保留率
错误事实引入率
后续任务成功率
```

### 8.2 实验 B：完整证据回溯测试

任务类型：

```text
法律文本
专利权利要求
代码修复
实验数据分析
数学推理
```

指标：

```text
证据引用准确率
原文细节恢复率
幻觉率
回答可审计性
```

### 8.3 实验 C：阶段边界测试

构造三类场景：

```text
阶段已完成
阶段未完成
阶段看似完成但存在隐藏冲突
```

比较对象：

1. token 阈值压缩。
2. SelfCompact rubric。
3. 多信号阶段边界判定器。

指标：

```text
误压缩率
漏压缩率
中间变量丢失率
后续任务恢复成功率
```

## 9. 效果预测

该机制不一定适合所有场景。

预测最有效的任务：

- 专利撰写。
- 论文整理。
- 代码 Agent。
- 长程调研。
- 多轮战略分析。
- 法律文档分析。
- 医学和科研证据综合。

原因是这些任务最怕：

```text
旧假设复活
证据丢失
错误摘要固化
阶段目标漂移
```

效果预期：

```text
短任务：提升不明显，可能过重。
长任务：目标一致性提升明显。
高精度任务：收益最大。
token 成本：相较全量上下文下降。
主要风险：阶段边界误判、状态蒸馏丢细节、证据回查成本增加。
```

## 10. 专利收敛方向

不建议主张：

> 一种上下文压缩方法。

该表述风险高，容易落入已有摘要、compaction、SelfCompact、MemGPT 等方向。

更建议主张：

> 一种基于阶段边界判定、结构化状态蒸馏和证据绑定的生成式模型上下文继承方法。

可能的独立权利要求核心步骤：

1. 检测当前任务是否到达阶段边界。
2. 将阶段内输入、输出、工具结果拆解为候选状态增量。
3. 对候选状态增量进行准入验证。
4. 为通过验证的状态增量绑定原始证据索引。
5. 将未通过项记录为废弃假设或禁止继承项。
6. 用通过验证的状态账本重新编译下一阶段初始上下文。
7. 在下一阶段以不包含完整历史的新上下文进程继续执行。
8. 当需要细节时，通过证据索引回溯原始历史。

## 11. 当前结论

SelfCompact 已经解决了“什么时候清理”的一部分问题。

我们要继续深入的是：

> 清理后什么有资格成为下一阶段的真实状态，以及如何保证它没丢证据、没混入废弃假设、没污染下一轮。

这比单纯上下文压缩更接近“上下文污染”的根源治理。
